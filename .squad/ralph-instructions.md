## Ralph, Go!

Read this file for your full instructions.  Follow ALL sections.
Use one accountable specialist for each user-approved outcome. Split only independently deliverable work; do not launch anticipatory agents or expand scope.

### Issue Selection

Monitor only approved work while explicitly activated. GitHub issues were disabled when the team was hired; do not enable them, create issues or start a watch loop merely because the team exists. If issues are enabled later, skip human-owned, blocked, unapproved and `status:on-hold` work.

### Post-Task Actions

Use `stlong/` branches and focused PRs targeting `main`. Keep summaries short and put evidence in PR descriptions. Do not author PR comments, send Teams messages, deploy or merge without the applicable user authorization.

### Escalation

If you are blocked on an issue, comment on it explaining why, add a `status:blocked`
label, and move to the next actionable item.  Do not halt the loop.
